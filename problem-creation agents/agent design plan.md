I wan to design a multi-agent workflow that creates calculation problems in physics based on user input.

0. The user input will be based on [input-scheme.yaml](./input-scheme.yaml). 
  
1. Agent 1: Checks and updates the input, and make the following changes
   1. check the formula and turn them into standard latex using best guess. (Directly edit the input)
   2. If any required items are missing or unclearly specifiec (currently everything under "other" is optional)
   3. Warning if number of scenarios is set to be greater than 10
   4. Ask user clarification questions if necessary, wait for user confirmation to proceed on calling Agents 2 and 3
   
2. Agent 2 (Scenario generator): Reads the scenario and scenario specifications, and existing list of scenarios (if any), then generates new scenarios not repeating the previous scenarios, until the number of intended scenarios is reached. Each scenario is described in 1-2 short sentences. Calls on Agent 3 to evaluate the scenarios. Record in the list how many times the list has been updated, starting from 0, and increment by one each time it receives the list.
   
3. Agent 3 (Scenario critique): Critiques each of the scenarios generated by agent 2 based on the scenario specification and suitability for use in a physics problem. If any of the scenarios are problematic, remove them from the list, then calls on agent 2 to fill up the list. If the list has been updated for more than 5 rounds, stop and tell the user that the LLM cannot find enough scenarios, and ask the user to adjust possible scenario list. If the intended list of scenarios are generated and passed the critique stage, for now, inform the user that all scenarios have been generated.

Note: Maybe the agents can automate some hard rules such as checking the number of scenarios and number of list updates using python? The agentic workflow will be extended by downstream agents to complete the task of problem generation.
